Design specification · v0.1

Every screen,
before a line of code.

Low-to-mid fidelity wireframes and full interaction specs for the 36 Crime Counsel Directory — the standalone client portal that replaces the emailed spreadsheet. Designed for people who instruct counsel under time pressure: fast, quiet, and premium.

Reference points: the restraint of Apple, the density and speed of Linear, the editorial calm of Stripe, and the content-first stillness of Notion.

Design language

The system a senior designer sets before drawing screens. Everything downstream derives from this. The guiding instinct: the interface should get out of the way of the content — counsel are the content — and every gram of visual weight should be spent where a decision is made.

Red is the barrister's brief ribbon — "pink tape." It is rationed: it only ever marks the single primary action or focal state on a screen. Nothing decorative is ever red.

01Client

Access

The threshold. Grants a client frictionless, revocable entry by magic link and sets the tone in one breath — this is a serious tool from a serious set, not a login wall.

Mobile · pre-submit
Mobile · "check your email"
  • 1 Single email field. Nothing else competes for attention.
  • 2 The one action, in ribbon red. Disabled until the address is valid.

Purpose

Passwordless entry that is quick for legitimate clients and revocable per firm. First impression of quality and restraint.

Layout

Single centred column, max 420px, on generous paper. Wordmark, one-line description of what the directory does, email field, primary button, quiet legal footer.

Components

Wordmark · email input · primary button · helper text · footer line. No global nav.

Interactions

Valid email enables the button. Submit swaps the form for a "check your email" confirmation echoing the address, with Resend (cooldown) and Use a different email. Enter submits.

Responsive

Identical on all sizes; field and button go full-width with ≥48px tap targets and comfortable side padding on mobile.

Loading

Button becomes Sending… with an inline spinner; field locks. No page skeleton — there is no data to fetch.

Empty

The pre-submit form is the empty state; the description carries the value proposition.

Error

Invalid format → inline field error, "Enter a valid email address." Unknown address → deliberately non-leaky success copy: "If that address has access, a link is on its way." Rate limit → "That's a few links now — try again in a minute."

Animation

Form→confirmation cross-fades with a slight upward slide (180ms, ease-out). No bounce, no confetti.

Hierarchy

Identity → one sentence of "what this is" → the action. The red button is the only saturated pixel on the screen.

02Client · hero screen

Directory

The centre of gravity. It answers one question — who can take this brief, at the right level and specialism? — in seconds. The whole dataset lives in the browser, so every filter is instant, with no spinner and no reload.

Mobile · filter sheet trigger
  • 1 Instant, type-as-you-go search across name, specialism and notable-case keywords.
  • 2 Sticky filter rail. CPS panel level and specialist panels sit first — the flagship filters for CPS users.
  • 3 Active-filter chips + live result count + "Clear all". The URL encodes this state so a view is shareable.
  • 4 Counsel card: name and panel-level badge lead; a top specialism as support; practice capacity noted.

Purpose

Turn a case need into a correct-grade shortlist in seconds — the reason the directory beats the spreadsheet.

Layout

Slim top bar (wordmark · search · count/sort). Desktop: sticky ~260px filter rail + responsive card grid (up to 4 cols). Mobile: search + a "Filters" button opening a bottom-sheet; single-column cards.

Components

Search · filter rail/sheet · filter pills · sort · result count · active-filter chips · counsel cards · capacity indicator.

Interactions

Every filter/keystroke updates results instantly and in place (client-side). URL reflects state. Card hover raises subtly and reveals "View profile". Tap → profile. Mobile sheet filters apply live against the count.

Responsive

Grid reflows 4→3→2→1 by width. Filter rail → bottom-sheet under 768px. Search collapses to an icon on the narrowest screens.

Loading

First paint shows a skeleton grid matching the final layout (shimmering card placeholders) and a skeleton rail. Thereafter filtering is synchronous — never a spinner; results simply reflow.

Empty

In-grid, directive, never a dead end: "No counsel match these filters," plus the binding reason ("No Level 4 counsel are on the RASSO panel") and two actions — relax the most-restrictive filter, or Contact clerks.

Error

If the cached payload fails to load: "Couldn't load the directory. Retry." with a retry button; the top bar stays. Never a blank screen.

Animation

Filter changes animate card positions with a FLIP transition + opacity for entering/leaving cards (150–200ms, ease-out). The result count rolls. Reduced motion → cross-fade only.

Hierarchy

Tools recede (quiet rail/top bar); cards dominate. Red is spent on exactly two things that anchor the shortlist: the panel-level badge (the credential CPS clients scan for) and the active-filter count.

Purpose

Support a confident instruct decision and route it to the clerks without exposing personal contact details.

Layout

Back link (preserves the directory's filter state). Desktop two-column: identity + panels + specialisms + bio + notable cases on the left; a sticky at-a-glance credentials + CTA rail on the right. Mobile stacks with a pinned action bar.

Components

Back link · identity header · panel/level badges · specialism tags · bio · notable-cases list · at-a-glance credentials card · primary CTA · share.

Interactions

Contact clerks opens the enquiry sheet pre-referencing this counsel. Share copies the deep link (toast: "Link copied"). Back returns to the exact filtered directory.

Responsive

Two-column → single column; the rail becomes a top credentials strip plus a sticky bottom CTA on mobile.

Loading

Usually instant from the cached payload. A cold deep-link load shows a profile skeleton (avatar block, title bars, badge pills).

Empty

No per-record empty. Absent fields (e.g. no notable cases yet) are simply omitted — no "N/A" clutter.

Error

Unknown, unpublished or revoked slug → "This profile isn't available," + "Back to directory." Handles drafts and revocations gracefully.

Animation

Enter is a short staggered fade/slide — header, then badges, then body — ~200ms total. The CTA has a calm press state, no bounce.

Hierarchy

Name + KC/level → credentials + CTA (the decision) → supporting detail. Red is the CTA and the panel-level badge, nothing else.

Contact clerks

Converts intent into a routed enquiry with zero friction, keeps the clerking team as the single channel, and protects counsel PII. It appears as a sheet over the directory or profile — the client never loses their place.

Send enquiry
Mobile · bottom sheet
  • 1 The referenced counsel arrives pre-filled as a removable chip; more can be added for a shortlist enquiry.
  • 2 Urgency as a segmented control — Routine / Soon / Urgent — the clerks' triage signal.

Purpose

Capture a clean, triageable enquiry and deliver it to the clerking inbox — the only contact path, by design.

Layout

Right-side sheet (~440px) on desktop; full-height bottom sheet with a drag handle on mobile. Referenced-counsel chip, then your name, firm, email, case type, urgency, message, and the send action.

Components

Scrim · sheet · counsel chip(s) · text inputs · case-type select · segmented urgency · primary/secondary buttons.

Interactions

Opens pre-filled from a profile or card. Submit → in-sheet success ("Enquiry sent — the clerks will reply to you@firm"). Esc / scrim / close dismisses, with a confirm if the form is dirty.

Responsive

Side sheet on desktop, bottom sheet on mobile; content and order identical.

Loading

Send shows a button spinner "Sending…" and locks fields; the sheet stays put.

Empty

A fresh form is the empty state; the message field placeholder guides — "Case type, hearing date, court, anything relevant."

Error

Inline validation on email/required fields. Send failure → non-destructive banner "Couldn't send. Retry," preserving everything typed. (If the MVP uses mailto: instead, this action opens the mail client; in-app is recommended so enquiries are logged.)

Animation

Sheet slides in on a 260ms spring while the scrim fades; success draws a check and cross-fades the content. Reduced motion → fade only.

Hierarchy

The referenced counsel and the Send action dominate; fields are calm and grouped; red only on Send.

06Admin · hero action

Member list

The clerks' work surface, and the beating heart of data quality. Keeping records current — a quick inline edit and the publish toggle — is the highest-frequency action in the whole product: one tap, optimistic, and live for clients within seconds.

Desktop · compact list (last row = draft)
Mobile · stacked, publish toggle in reach
  • 1 Inline publish toggle — the hero. One tap moves a record between draft and published, optimistically, with a quiet "Saved" tick, live for clients in seconds.

Purpose

Keep the dataset accurate and current with minimal clicks; make editing and publishing a fast, low-risk habit.

Layout

Compact, Linear-style list. Toolbar: search · status filter · Add member. Columns: member · call year · panel/level · publish toggle · status · last updated · edit.

Components

Data list · inline publish control (Draft / Published) · status badge · search · add button · row menu.

Interactions

Toggle updates optimistically, then revalidates the client payload. Row click → editor. Search-as-you-type. Bulk-select later.

Responsive

Table → stacked cards under 768px; the toggle stays thumb-reachable.

Loading

Skeleton rows. Toggling is optimistic — no full reload; a failed save reverts the control and shows a toast.

Empty

No members → "No members yet. Add your first, or import from Excel," with Add (primary) + Import (secondary). Filtered-empty → "No members match" + clear.

Error

Save failure → control reverts, toast "Couldn't save. Retry." Nothing is ever silently lost.

Animation

Crisp toggle state change; "Saved" tick fades in and out. Row hover highlight. Quick and functional — no flourish.

Hierarchy

The list is the surface; the publish column carries the most weight (it's how records go live). Red = the "Published" state and the Add action.

States & motion

The connective tissue that keeps the product feeling premium under real conditions — slow networks, dead links, and quiet moments — plus the rules that keep motion and accessibility consistent everywhere.

Error boundary

Loading philosophy

Content loads behind skeletons that mirror the final layout — never spinners. Spinners are reserved for discrete actions (submit, save). Because the directory is cached in the browser, most navigation is instant after first load.

Not found (404)

"This page isn't here." One route home. Branded and calm; the same treatment on client and admin sides.

Global error

"Something went wrong. Reload." A quiet error id for support. The error never leaks internals or blames the user.

Offline / stale

If the cached directory is served offline, a subtle chip reads "Showing the last saved version" rather than failing.

Toasts

Bottom, brief, one line, verbs that echo the action: "Published," "Link copied," "Saved." Auto-dismiss; never stack noisily.

Motion rules

Micro 100–120ms · UI 180ms ease-out · result reflow 150–200ms FLIP · sheets 260ms spring. Motion always explains cause and effect.

Reduced motion

prefers-reduced-motion collapses all movement to a simple opacity fade — no slides, springs, or position shifts.

Accessibility floor

WCAG 2.2 AA: visible keyboard focus, full keyboard navigation, AA contrast, labelled controls; sheets and modals trap focus and close on Esc.

Voice

Sentence case, plain verbs, no filler. Buttons say what happens ("Send enquiry," not "Submit"), and the name is kept through the flow. Errors direct; empties invite.

The one rule

Spend boldness in one place per screen — the red focal action — and keep everything else quiet. Elegance is executing that restraint precisely.

What isn't drawn here. Phase-2 admin surfaces — client-access management and the audit log — reuse the member-list patterns above (compact list, inline actions, guarded destructive operations) and don't warrant new primitives. Worth wireframing once their exact fields are settled alongside the access-model decision (D1 in the PRD).
